## 已定位的代码与待确定原因

- `core/windowing.py:fit_viewport`：每约 2 秒可改变 window geometry，调用 `update_idletasks()`，然后才 xview/yview；这会允许中间帧被展示，是黑框/视觉跳变首要候选。Canvas scrollregion 是整屏，实际 viewport 靠滚动定位。必须避免 geometry 与内容原点不同步的可见绘制，特别是底/右边缘滚动钳制；不要用每帧 hide/show 遮掩闪烁，也不要退回永久全屏画布导致内存大幅回升。
- 黑框其他候选：透明色键背景在原生 resize/move 擦除期间被涂黑；single/merged PhotoImage 切换或裁剪边缘色键处理。现有“先 itemconfig 再释放旧图”顺序是必要保护，不能破坏。
- `core/world.py` WorldModel/WorldView clamp 使用全屏 60px；`body/base.py:_integrate` 使用全屏 80px，墙线穿越时截断位移；StateArbiter 对外部位置另用 WorldModel clamp。多个不同边界、任务栏未扣除、Tk viewport 坐标原点不同步都可能造成用户所说瞬移。不能把候选当已复现原因，最终说明按实际实现诚实写。
- `perception/mouse.py` 已采样速度/向量并发 WIND，但风强只取总鼠标速度与距离，没有明确朝向宠物的闭合速度；需要扩展此共享路径而非重复采样鼠标。
- `body/base.py:_apply_escape` 在 sprint 中 min(sprint, escape_sprint_cap)，单纯提高 sprint 会被 cap 抵消；脑有固定 intensity=1 的路径，也不能靠改一个阈值实现“风压越大跑越快”。
- `core/app.py:_build_body`、`_rebuild_with_speed`、set_pet_scale 会影响速度参数；已有糖珠 buff。新增用户倍率与临时 buff 要组合，不能反复乘法累积，不能每次滑杆重建 body 清零速度/步态造成顿挫。
- 当前设置的“启动时打开控制面板”只是 panel_visible，不是系统自启动，需区分两个开关。

## 要实现的行为

### 1. 透明窗口与连贯边界

统一窗口与 Canvas 的屏幕坐标映射，一次展示一致的 resize/move/scroll 结果。可用简单 Win32 原生调用/画布原点重构，但选最小且不会暴露黑底的方案；如禁止重绘，务必 finally 恢复，失败安全，不造成永久黑窗或死锁。保持 PhotoImage 引用生命周期、单宠/合成组转换和拖拽 x_root/y_root 正确。
Windows 用系统当前显示器实际 work area（任务栏在底/顶/左/右都适用），提供安全跨平台回退；不要写死 40/48px 任务栏高度。启动和必要节流刷新即可，不要每宠每帧 Win32 查询。
运动目标、实际积分和外部仲裁采用一致可用边界与身体留白。靠近边界提前减速/转向，碰撞按本次位移连续截断或贴边滑行，保留剩余分量，不反向到远处、不随机重置位置、不把从边缘返回的宠物拉回 60/80px。工作区变动、拖拽放到边界外后，要沿有限速度回到可用区域，不单帧夹回；显式用户召回/重新生成不属于自主爬行瞬移，但不要改其语义。角落、高速和自动隐藏任务栏都要从逻辑上考虑。

### 2. 用户速度与鼠标惊逃

全局设置“爬行速度 / Crawling speed”，范围 0.5×–8×，默认 2×（使现状明显更快）；即时显示倍率、保存重启恢复，提供恢复 2×，不与单宠大小混淆。允许 0.5/1/2/3/4/6/8 的易用档位或直接滑杆，选控件最简单的实现。
倍率对已有/新增/召回宠均有效，与 buff 和大小按基准参数一次计算。巡航、逃跑上限、必要加速度同时适配；不能留下旧 escape_sprint_cap 让 8×无效，绝对安全上限保证 dt 延迟时不会穿屏。不要把全局时间 dt 乘倍率，否则饥饿、记忆、食物和飞行节奏全被改坏。升降档保留当前位置/朝向/速度并有限加减速，保留 planted 足和步态相位。
鼠标朝宠物逼近的闭合速度 = 鼠标速度向量在“鼠标 → 宠物”方向的正投影；与距离衰减共同形成风压（速度平方是可用的廉价拟真近似，归一化后有上限）。静止/远离弱或无逼近风压，擦身保留适当弱空气扰动。突然快速靠近触发有限反应延迟、朝离开鼠标方向转向、平滑加速；风压持续越强，最终逃速越高，鼠标停下后平滑恢复。兼顾飞行果蝇既有起飞反应，不能强制所有宠每帧 ESCAPE、破坏觅食/暂停/抓握/信任行为，也不能定时瞬移来“逃跑”。

### 3. 高速细线拖尾

只在真实位移速度足够高时显示，速度越快线越长（单调、有上限），方向沿近期实际轨迹；停下后 100–200ms 内消退，暂停、抓握、隐藏、移除、退出要清理。线条轻薄、不盖住蟑螂身体，默认开启，设置可关闭。
优先复用少量 Canvas line 项而非每帧新增图像。每宠历史 deque 上限 6–8 个位置/时间，每宠最多 3–5 段、长度上限约 200–240px；10 宠最多约 50 个线项。不要未限制地积累点、PhotoImage、全屏蒙版。按实际速度与体长选合适出现阈值；拖尾参与 viewport bounds，但避免长尾造成频繁 resize 和黑框回归。确保点击穿透/投喂/拖拽仍可用，尽量别让装饰线截获鼠标。

### 4. Windows 用户级自启动

独立复选框“开机自启动 / Start with Windows”，默认关闭，只有用户在产品里主动勾选才写 HKCU Run（stdlib winreg；无需管理员）；取消只删本程序命名的项。正确引号封装当前便携 EXE 的绝对路径，路径含空格/中文也有效，附 `--autostart`（若实现）让开机启动留在托盘，手动启动仍遵循 panel_visible。源码运行可用 pythonw + 绝对入口路径，或者清楚标注只支持便携版，选低成本正确路线。
读取真实注册表状态显示勾选，失败回滚开关并给双语错误，不把 config=true 当系统已成功注册，不每次启动无条件写系统。便携文件夹移动后需主动重新启用以更新路径，在 README 解释。实现阶段不要真的改本机自启动，不启动额外服务、计划任务或后台守护。
自启动若涉及重复进程，用简洁当前用户单实例守卫避免第二次登录启动复制宠物窗口，保留现有调试入口合理行为。
