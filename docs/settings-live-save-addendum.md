# v0.2.0 追加要求：设置可用且实时保存

用户在 OC 执行期间补充：目前大小不能选择；语言 Combobox 未显示默认项；“保存并退出”直接退出整程序不合预期。所有设置有改动立即更新和保存，不需要保存按钮。

这是当前 v0.2.0 必须完成的范围，不能只做运动部分就交付。保留本轮其他实现和提交，最终重建同一个 v0.2.0 包。仍然不运行测试/审查/桌宠实际验证，不修改本机真实配置/自启动。

1. 设置窗口在打开时明确显示当前语言、大小和速度，不留空；所有 Tk Variable 由窗口/面板保持强引用直到窗口关闭，避免局部 StringVar 在函数结束后 `__del__` unset Tcl 变量。语言当前代码 `language = tk.StringVar(...)` 仅为局部且事件回调不捕获它，是空白默认项的重要根因候选。用字段或统一窗口 variables 保存生命周期，关闭时释放。
2. readonly Combobox 显式 `current()`/`set()` 对应现值，初始值与 values 一致；语言 zh-CN/en 任一时都显示其自称；大小显示实际 scale。
3. 宠物大小选择必须可用：设置打开时优先关联选中的可见宠物；若没有选择但有可见宠物，自动选一只而非静默禁用。若仅隐藏宠，提供明确的宠物选择/召回指引；用户选择不同宠物时要清楚显示目标，更新大小，不沿用过期 pid。可添加精简“当前宠物”下拉选择（按 ID 保存），不要让用户去另一个窗口寻找才能用设置。
4. 排查 Combobox 弹出列表无法点击：Tk popdown 是额外原生窗口，可能超出父设置矩形；app._panel_contains 的投喂全局鼠标钩子和 topmost 透明舞台不能吃掉下拉点击。只将本程序 UI（含 popdown）作为穿透区域，不能为了修控件禁用整个点击投喂功能或对所有窗口放行。使用 Tk 主线程可安全采集的 popdown bounds/映射或 Win32 所属进程命中判断，不从钩子线程调用 Tk。
5. 实时保存：语言/大小/速度/拖尾/开机自启动/启动时打开面板各自 changed 回调立即生效，持久化成功保持，失败给双语提示和合理回退。禁止打开设置/切换语言时因程序填值触发保存或写注册表；拖动滑杆可节流磁盘写入，但释放鼠标必须完成最后一次保存。
6. 去掉“保存并退出程序 / Save and quit”这种设置页流程。用“关闭设置 / Close settings”只 destroy 该设置窗口（最好底部提示“改动会自动保存 / Changes are saved automatically”）。退出程序维持托盘明确“退出 / Quit”，或单独清楚标明“退出程序 / Quit application”且不冒充设置保存动作。
7. Esc、设置右上角 X、关闭按钮都只关闭设置，不停止 app，不隐藏主面板。窗口重开保持所有当前值和语言。处理中英布局、Tk变量销毁和已选宠物ID，不能重建设置后遗失关联。
8. 更新双语 README、release notes、PROGRESS；最终补充提交并构建 ZIP，回报这些追加项具体修复。不要宣称未运行的真实交互已经通过。
